# ADR 0005. Snapshot files are emitted at the frozen `/v1/*` URLs

- **Status:** accepted
- **Date:** 2026-09-02
- **Decider:** ROLE 6 (integration), on the snapshot-URL seam (the hard blocker)

## Context

Role 2's PWA fetches the frozen ENDPOINTS surface (`/v1/streams`,
`/v1/conditions/latest.json`, `/v1/stocking/{state}.json`, `/v1/hatch/{regionId}/{month}.json`,
`/v1/shops/{state}.json`, `/v1/reports/recent.json`, plus the bundled content pack at
`/content/taxa.json` + `/content/patterns.json`). Role 3's builder wrote
`apps/web/public/data/*` — nothing answered `/v1/*`, and nobody emitted hatch charts or the
content pack into the web app.

## Decision

Extend Role 3's snapshot builder to write **at the served URLs**, under
`apps/web/public`:

```
v1/streams.json                    (Stream[] — /v1/streams answered live with ?state= filter)
v1/conditions/latest.json          (ConditionSnapshot[])
v1/stocking/{state}.json           (StockingEvent[])
v1/shops/{state}.json              (Shop[])
v1/reports/recent.json             (ShopReport[])
v1/hatch/{regionId}/{month}.json   (HatchChart — 11 regions × 12 months)
content/taxa.json                  (BugTaxon[] — bare array)
content/patterns.json              (FlyPattern[] — bare array)
```

- Hatch charts + the two content payloads derive from **Role 4's built content pack**
  (`packages/content/dist/pack`) in the same regeneration step; every payload is
  re-validated against the frozen Zod schemas before writing (pack extras such as the
  inlined per-taxon SVG are stripped — the PWA draws its own order-level art).
- The old `data/` layout is **dropped**, not kept as an alias — nothing shipped against it
  (pre-launch), and one canonical layout keeps the Workbox runtime-caching rules honest.
- Snapshots stay gitignored build artifacts (regenerated by cron/deploy).
- Because conditions must stay fresh between web builds, the web production build precaches
  only `content/**` + `v1/hatch/**`; the remaining `/v1/*` files are runtime-cached
  (NetworkFirst) — see ADR 0004.

## Consequences

- The PWA's `apps/web/src/lib/endpoints.ts` needs no changes; the builder now speaks the
  frozen surface exactly.
- `pnpm --filter api snapshots` requires the content pack to be built first
  (`pnpm --filter @trout/content build`, already part of `pnpm -r build`); without a pack
  the run emits a warning and still refreshes the DB-derived snapshots.
- `/v1/streams?state=TN` is answered by the API route reading `v1/streams.json` (ADR 0004).

## Alternatives considered

- Re-point `ENDPOINTS.streams` at `/v1/streams.json` via contracts-v1.0.1 — rejected: it
  would burn the additive-change budget on a serving detail answerable in one route, and
  `?state=` filtering still needed live code somewhere.
- Keep `data/` as a deprecated alias — rejected: two layouts for one payload invites a
  stale-copy bug exactly like the seam this ADR closes.
