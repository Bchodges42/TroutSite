# 0016. Angler watchlist alerts

- Status: implemented on a review branch; production enrollment requires owner configuration and installation of the scheduled job.
- Date: 2026-09-30

Visitor push is an explicit opt-in exception to local personal storage. The server keeps a random subscription capability, browser push endpoint, encryption keys, selected water/rule parameters, timing state, and an optional browser diagnostic string. These are pseudonymous personal data. A database or browser-storage leak can expose a user's watched waters. Logbook entries, photos, trips, and device location are not collected by this service.

The platform's push provider delivers notifications to the browser. Enrollment must explain this involvement, the server data stored, deletion, and retention. Push endpoints are restricted to HTTPS Chrome/Firefox/Apple/Windows browser push services. Arbitrary hosts, credentials, fragments, and ports are rejected; P-256/auth keys are validated. Re-registering an endpoint returns its capability only with the original matching keys. Key replacement requires a new browser subscription; an endpoint alone is never authorization.

The /v1/watches/config, subscription, rule-list/create/delete, and unsubscribe routes are live, no-store, and excluded from service-worker caching. Mutation routes require JSON, bounded bodies, and origin/rate checks. Request logs exclude query strings, receipt codes, and subscription capabilities. The random 128-bit subscription ID authorizes access to that watchlist; treat it as a secret. Missing or invalid VAPID keypairs disable enrollment.

Evaluation reads existing snapshot files, never upstream providers. Each metric uses its own observation time, rejects missing/stale/future/invalid evidence, and fires only in the requested threshold direction after hysteresis. The first decisive reading sets a baseline without notifying. The reverse transition silently rearms the rule. Quiet hours use an explicit IANA zone; Tennessee spans Central and Eastern time. Migration 022 preserves the existing Central-time setting while new rules can specify their zone.

Stocking watches use the same county/alias association as water pages and persist publication identities independently of fetch time. A future scheduled day is not a repeatable notification clock. Copy identifies published schedules and never claims a planned release was completed. Reports use publication instants. Cooldowns, quiet hours, and digest bundling limit notification volume.

Source-outage watches are separately selectable for flow or temperature. Historical provider readings establish which metrics a water supports; an absent unsupported measurement stays unknown. Freshness uses the metric's own observation time and the same three-hour condition horizon. The first known availability state is silent, then loss and recovery notify once each. Quiet hours, cooldowns, failed sends and dry runs leave the transition pending. Availability notices never infer fishing quality or safety. Migration 023 preserves existing rules, deletion cascades and monotonically increasing IDs.

Only successful real delivery advances notification memory. Failed delivery remains retryable and fails job health; a stub records payloads without consuming a real transition. HTTP 404/410 removes dead endpoints and their rules. Active subscriptions are retained for at most 180 days without a user visit; unsubscribe deletes server records immediately. Logs contain counts/statuses, never payload keys or endpoints.

ingest --job=watchlists is an explicit dispatcher job. Production uses infra/evaluate-watches.sh, guarded by the verified deploy stamp, and the trout-evaluate-watches schtasks entry every 15 minutes. Dev node-cron calls the same dispatcher. Health and the owner dashboard expect this job when either push or corrections are configured: the dispatcher also purges terminal corrections after their retention window, even with push disabled. No task is installed or production notification sent during development verification.

The worker displays notifications when the app is closed and handles clicks using validated same-origin water links. Unsupported browsers keep a device-local watchlist; its UI capability and limitations must be described accurately. VAPID key rotation, actual device delivery, and owner rollout remain explicit operations steps. Automated checks use synthetic subscriptions and local encrypted-request construction, with no real recipients.
